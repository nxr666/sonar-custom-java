Non-standard (vendor-specific) SQL functions vary across database vendors and versions. SQL standard functions are not targeted by this rule. Keeping mapper SQL close to ANSI basics and moving formatting, parsing, and calculations to Java reduces migration risk and keeps behavior consistent in tests.

Noncompliant Code Example

<select id="findUser" resultType="User">
  SELECT id, DATE_FORMAT(created_at, '%Y-%m-%d') AS createdDate FROM users WHERE id = #{id}
</select>

Compliant Solution

<select id="findUser" resultType="User">
  SELECT id, name FROM users WHERE id = #{id}
</select>

Normalize or transform values in the service layer before persistence or after load, instead of calling vendor-specific functions in XML.
