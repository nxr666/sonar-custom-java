Writing INSERT INTO table VALUES (...) without an explicit column list is fragile: schema changes or column order changes can silently corrupt inserted data.

Noncompliant Code Example

<insert id="saveUser">
  INSERT INTO users VALUES (#{id}, #{name}, #{email})
</insert>

Compliant Solution

<insert id="saveUser">
  INSERT INTO users (id, name, email) VALUES (#{id}, #{name}, #{email})
</insert>
